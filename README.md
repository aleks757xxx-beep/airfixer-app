# PostFixer — приложение для постинга AirFixer

Cloudflare Worker (Hono + TypeScript) + интерфейс React/Vite/Tailwind (Material Design 3, только тёмная тема). Ролики в R2 (`airfixer-video`), данные в D1 (`postfixer`).

Публикация **напрямую**: Instagram и Facebook (Meta Graph), Threads, YouTube (Data API, загрузка частями), Telegram-канал (бот). **Через Buffer**: TikTok, Google Бизнес.

- Адрес: https://app.airfixer.ge (служебный *.workers.dev выключен)
- Деплой: автоматически при пуше в `main` (Workers Builds). Перед деплоем wrangler сам собирает интерфейс (`npm run build:web`).
- База: таблицы создаются/обновляются сами при первом запросе (`worker/lib/migrate.ts`, файлы `migrations/*.sql`). Новая миграция — новый файл + строка в `MIGRATIONS`; старые не менять.

## Секреты (Cloudflare → Settings → Variables and Secrets, тип Secret)
`APP_PASSWORD`, `UPLOAD_TOKEN`, `TOKEN_KEY` (шифрование токенов соцсетей и ключа кода, base64 32 байта), `BUFFER_API_KEY`, `META_APP_SECRET`, `THREADS_APP_SECRET`, `GOOGLE_CLIENT_SECRET`, `TG_BOT_TOKEN`.
ID приложений (Meta, Threads, Google) — не секреты, лежат в коде.

## Структура
- `worker/` — сервер: `index.ts` (маршруты и cron), `middleware/` (вход, заголовки безопасности, CSRF), `routes/`, `services/` (по соцсетям: `meta.ts`, `threads.ts`, `youtube.ts`, `telegram.ts`, `buffer.ts`/`publish.ts`; прямая очередь — `direct.ts`; история и статистика — `history.ts`), `lib/`.
- `web/` — интерфейс: `features/` (экраны), `components/m3/` (компоненты M3), `api/` (запросы + React Query).
- `shared/` — Zod-схемы, общие для сервера и интерфейса.
- `scripts/icons.mjs` — пересобрать значки (`web/components/m3/icons.ts`) из `@material-symbols/svg-400` по списку `scripts/icons-list.txt`.

## Cron
- Каждую минуту: прямые посты, у которых подошло время (загрузка YouTube — по 64 МБ за раз), цифры опубликованных постов, уведомления (посты, работа Claude); в :07 каждого часа — посты Buffer.
- Раз в сутки (03:00 UTC): уборка хранилища, продление ключей Threads, проверка всех подключений, копия истории Buffer, чистка журнала (год) и кэша.

## Уведомления
Бот `TG_BOT_TOKEN` (@fixerairbot) пишет владельцу в личный чат (ID чата — `app_settings.notify_chat_id`, задаёт Claude: `PUT /api/v2/ingest/agent/notify-chat`). Виды: пост не вышел, пост вышел, подключение сломалось (раз в сутки), Claude выполнил задание / монтаж готов. Включаются и выключаются в «Настройках». Отправленное отмечается (`direct_posts.notified_status`, `notify_log`) — повторов нет.

## Правила публикации
Решение владельца 09.11.2026, по исследованиям. Числа лежат в `shared/rules.ts`, статья — в «Настройки → Правила публикации» (`web/features/rules/RulesArticle.tsx`), ссылка «Правила» есть в окне поста.
- **Норма** постов в неделю на соцсеть: 3, Google Бизнес — 1. Расписание не ставит чаще и сдвигает дальше.
- **Часы выхода** по Тбилиси: будни 18–22, выходные 10–22 (когда владелец может ответить на комментарии). Внутри них — лучший час канала.
- **Один ролик в несколько соцсетей** («В очередь»): следующая соцсеть — через 3 дня, первой та, где больше просмотров (`spreadSlots`). Если дата выбрана вручную, посты ставятся как выбрано.
- **7 дней без постов** и ничего не запланировано — напоминание в Telegram (ночной cron, `checkIdle`), не чаще раза в неделю на соцсеть.
- **Повтор** — не раньше 90 дней, с новой подписью и другим началом.

## Повтор роликов
У ролика в «Библиотеке» галочка «Можно повторять» (`media.repostable`). Список «Можно повторить» (`GET /publish/reposts`): в соцсеть, где ролика не было, — сразу; где был — через 90 дней (`worker/services/reposts.ts`). Сверху — ролики с лучшим результатом относительно обычного для канала. «Повторить» открывает окно поста с прошлой подписью. Сам ничего не публикует.

## Пометка исходников
Чтобы в «Исходниках» было видно, что уже вошло в ролики. Решение владельца 09.11.2026 (`worker/services/sources.ts`):
- **Когда:** как только у смонтированного ролика появился запланированный пост (любой, кроме черновика). Если все посты сняли до выхода, пометки уходят. Старые ролики 1–18 не трогаем.
- **Номер ролика:** одна нумерация со старыми роликами в «Готовом», следующий номер — 19. Номер ролик получает, когда его впервые запланировали. Ролик в «Готовом» переименовывается: «Монтаж #1 v1 Тема.mp4» → «19 Тема (заказ #1 v1).mp4».
- **Имя исходника:** «#19 IMG_1234.MOV». Если взят кусок — «#19 (0:12–0:20) IMG_1234.MOV». Если файл вошёл в два ролика — «#19 #23 IMG_1234.MOV».
- **Что делает Claude:**
  1. После каждого монтажа: `PUT /api/v2/ingest/agent/media/:id/sources {items:[{folder, file, from?, to?}]}`.
  2. На Mac, перед выбором материала: `GET /api/v2/ingest/agent/sources/renames?gotovoeMax=<наибольший номер на диске>`.
  3. Для каждого ролика из `gotovoe`: сначала `POST /media/:id/rename {name}`, потом переименовать файл (и «.tg.mp4»).
  4. Для каждого файла из `sources`: переименовать файл, потом `POST /sources/renamed {folder, from, to}`.

## Работа с видео
Решение владельца 11.11.2026 (заменила «Правки по секундам» v0.29). В «Библиотеке» у ролика большая кнопка «🎬 Работа с видео», у черновика заказа — такая же. Окно (`web/features/review/VideoWorkspace.tsx`):
- **Заметки** — точка или отрезок («Начало» / «Отметить» конец) или без времени; тип: Убрать · Кадр · Субтитр · Звук · Кружочек · Другое; до 4000 знаков, сколько угодно. Хранятся на сервере сразу (таблица `review_notes`), правятся и удаляются, пока не отправлены. Шкала под плеером показывает заметки.
- **Звук** — уровни: громкость голоса, бас, гнусавость (слышно сразу в плеере через Web Audio), шум, паузы, музыка (применяет Claude при монтаже) + комментарий. «Сохранить для этого ролика» (`media.voice`) или «Сделать моими по умолчанию» (`app_settings.voice_default`). Формула фильтров одна для плеера и для ffmpeg — `shared/review.ts` (`voiceChain`, `voiceFfmpeg`).
- **Ответы** — раунды правок (`review_rounds`): что отправлено, звук, ответ Claude по каждой заметке (сделано / не сделано) и общий ответ.
- «Отправить Claude» = новый раунд из всех черновиков + текущий звук. У черновика заказа заказ переходит в «Правки — ждёт Claude».

Для Claude: `GET /api/v2/ingest/agent/reviews` (открытые раунды: ролик, заметки, звук, готовый фильтр `voiceFfmpeg`, `voiceText`), `POST /api/v2/ingest/agent/reviews/:roundId {reply, notes:[{id,status:"done"|"wontdo",reply}]}` → уведомление «Claude ответил на правки» в Telegram.

## Корзина
Решение владельца 11.11.2026. В библиотеке нужны только ролики для публикации.
- **Сама:** когда версию ролика ставят в публикацию, более старые версии того же ролика (`versionBase`: «19 Мойка в клубе» = «… v9», «Монтаж #3 v1/v2 …»), которые никуда не выходили, уходят в корзину (`media.trashed_at`, `trash_reason = old_version`). Проверка — при открытии библиотеки и ночью.
- **Вручную:** «🗑 В корзину» у ролика. Ролик со стоящим в расписании постом — нельзя (сначала снять посты).
- **Корзина** внизу «Библиотеки»: «↩ Вернуть» (вернули — сама больше не уберётся, `trash_reason = kept`) и «Удалить сейчас».
- **Через 14 дней** ночной cron удаляет насовсем: R2 и карточка (`deleted_at`); файл в «Готовом» стирает Claude по `GET /api/v2/ingest/deleted`. Номер ролика и пометки исходников не теряются.
- Для Claude: `POST /api/v2/ingest/agent/media/:id/trash`. Код: `worker/services/trash.ts`, миграция `0022_trash.sql`.

## Резервная копия
Решение владельца 10.11.2026. «Настройки → Скачать копию данных» или для Claude `GET /api/v2/ingest/agent/backup` — все таблицы D1 одним JSON (`worker/services/backup.ts`). Без сессий, кода входа, ключей входа и токенов соцсетей. Полный план восстановления — папка «AirFixer-бэкапы/Резерв приложений» на Mac и ветка `backup` в `airfixer-crm`.

## Проверка перед отправкой
- `npm run check` — типы (строгий TS, без неиспользуемого кода) + сборка интерфейса.
- `npm test` — автотесты (~20 с): локальный Worker с чистой базой + заглушки всех соцсетей (`tests/harness.mjs`, `tests/mocks.mjs`, `tests/app.test.mjs`): безопасность, вход, автозагрузка, публикация в Instagram/Facebook/Telegram/YouTube/Threads, статистика, история, вставки, лучшее время, правила публикации, повтор роликов, пометка исходников, перебор пароля.
- **Выкладка проверяется сама:** в Workers Builds `wrangler deploy` запускает `scripts/build.mjs` → типы + сборка + тесты. Упал хоть один тест — выкладки нет, на сайте остаётся прежняя версия. Новая функция — новый тест в `tests/app.test.mjs`.

## Вход
Пароль (`APP_PASSWORD`) + 6 цифр из «Паролей» Apple. Вход без срока — до «Выйти на всех устройствах» (раздел «Настройки»); на доверенном устройстве код больше не спрашивается. 8 неверных попыток с одного IP → пауза 15 минут. Необязательно — Face ID / Touch ID (ключи входа).

**Потерял телефон с кодами:** Cloudflare → Storage & Databases → D1 → `postfixer` → Console → выполнить
`DELETE FROM auth_settings; DELETE FROM trusted_devices; DELETE FROM sessions;` → при следующем входе приложение предложит подключить код заново.
